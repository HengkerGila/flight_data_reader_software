# Building a standalone executable

PyInstaller packages the interpreter, the application and every library it
loads into one folder with an executable at the top. It only builds for the
operating system it runs on, so the Windows `.exe` must be built on Windows.

## Windows

1. Install **Python 3.12, 64-bit** from python.org (tick "Add python.exe to
   PATH" in the installer).
2. Copy the project folder to the Windows PC (or clone it).
3. Open a command prompt in the project folder and run:

   ```bat
   packaging\build_windows.bat
   ```

   The script creates `.venv-win`, installs the application with the OCR
   extra plus PyInstaller, and runs the spec. The first run downloads
   PySide6, PyMuPDF, onnxruntime and RapidOCR (~500 MB) and takes several
   minutes.

4. The result is the folder `dist\ARINC717Reader\`. Start
   `ARINC717Reader.exe` from there, or copy the **whole folder** to another
   PC. The executable does not work on its own: it needs the DLLs, Qt
   plugins and OCR models beside it.

   `ARINC717Reader.exe path\to\dataframe.adb` opens that dataframe at start.
   A demo dataframe and document are in `dist\ARINC717Reader\examples\`.

5. The script ends by running the build's self-test. You can repeat it at
   any time from a command prompt:

   ```bat
   dist\ARINC717Reader\ARINC717Reader.exe --selftest
   ```

   It prints one PASS/FAIL line per check (decoder closed loop, ADB codec,
   GUI construction, PDF import through PyMuPDF, OCR model loading) and ends
   with `SELFTEST OK`. OCR is the only optional check.

Because the build has no console window, log output goes to
`%LOCALAPPDATA%\arinc717_reader\arinc717-reader.log`. Look there first if
the window does not appear.

## MSI installer (one file, click to install)

`packaging\build_msi.bat` wraps `dist\ARINC717Reader\` into a single Windows
Installer package, `dist\ARINC717Reader-<version>-x64.msi`, using the
[WiX Toolset](https://wixtoolset.org) (v5 or newer). The package definition is
`packaging\windows\ARINC717Reader.wxs`.

One-time setup on the build PC:

1. Install the **.NET SDK** (8 or newer) from dotnet.microsoft.com.
2. In a new command prompt: `dotnet tool install --global wix`
   (later: `dotnet tool update --global wix`). The build script adds the UI
   extension itself.

Then, after `packaging\build_windows.bat` has produced the folder (it calls
the MSI step automatically when `wix` is on the PATH):

```bat
packaging\build_msi.bat
```

What the installer does:

- installs everything to `C:\Program Files\ARINC 717 Data Reader\` (the
  wizard lets the user pick another folder), for all users, with a UAC prompt;
- creates a Start Menu entry and a desktop shortcut, both with the
  application icon (`packaging\icon.ico`, generated by `make_icon.py`);
- registers the product in Settings > Apps for repair and uninstall;
- upgrades in place: installing a newer version removes the previous one
  first (the `UpgradeCode` in the `.wxs` must never change; bump `version` in
  `pyproject.toml` for every release, the script reads it from there);
- writes nothing else to the machine. Settings live in the user's registry
  hive (`HKCU\Software\arinc717_reader`), the log in
  `%LOCALAPPDATA%\arinc717_reader\`, recordings wherever the user saves them.

Useful command lines:

```bat
msiexec /i ARINC717Reader-0.1.0-x64.msi /l*v install.log     REM wizard + verbose log
msiexec /i ARINC717Reader-0.1.0-x64.msi /qn                  REM silent install
msiexec /i ARINC717Reader-0.1.0-x64.msi /qn ADDLOCAL=Main    REM silent, no desktop shortcut
msiexec /x ARINC717Reader-0.1.0-x64.msi /qn                  REM silent uninstall
```

Expect the `.msi` to be roughly half the size of the folder (the cabinet is
compressed) and the install to take about a minute.

Things the installer does not cover:

- **Code signing.** The package is unsigned; a file downloaded from the
  internet shows the SmartScreen "unknown publisher" warning (More info >
  Run anyway). Copied over a network share or USB stick it installs without
  that prompt. Signing needs a code-signing certificate and `signtool`.
- **The FTDI driver** for the USB-UART cable. Windows 10/11 install it through
  Windows Update when the cable is first plugged in; an offline PC needs the
  FTDI VCP driver package.

Troubleshooting the MSI build:

| Message | Cause / fix |
| --- | --- |
| `wix` is not recognized | The .NET tool is not on the PATH of this prompt: open a new command prompt, or run `dotnet tool install --global wix` again. |
| unknown element `Files` | WiX older than v5: `dotnet tool update --global wix`. |
| extension version mismatch | `wix --version`, then add the matching extension, e.g. `wix extension add -g WixToolset.UI.wixext/5.0.2`. |
| ICE warnings about shortcuts / registry key paths | Expected for non-advertised shortcuts; they do not affect the package. |
| `Another version of this product is already installed` | Same version already installed and the package was rebuilt with the same version: uninstall first, or bump the version. |

## Size

The folder is around 500 MB, most of it OpenCV (pulled in by RapidOCR, and
on Linux it brings ffmpeg and GTK along), onnxruntime and Qt. Swapping
`opencv-python` for `opencv-python-headless` in the build venv before
running PyInstaller removes the GUI and video libraries and is safe: the
importer only uses OpenCV through RapidOCR's image preprocessing.

## Linux (validation build)

```bash
packaging/build.sh
dist/ARINC717Reader/ARINC717Reader examples/demo_256wps.adb
```

## What the spec does

`arinc717_reader.spec` collects the RapidOCR model files (`*.onnx`,
`config.yaml`) and the PyMuPDF binaries explicitly, because they are loaded
at run time and static analysis does not see them; collects the package's
own data files, in particular the English OCR recognizer
(`arinc717_reader/dataframe/pdf_importer/models/en_PP-OCRv3_rec_infer.onnx`,
9 MB, the importer's default recognizer); names the lazily imported OCR
modules as hidden imports; bundles the two example files; and excludes the
Qt modules the application never uses (WebEngine, Qml, Multimedia, …) to
keep the folder around 350 MB instead of 700 MB.

## Common problems

| Symptom | Cause / fix |
| --- | --- |
| Windows SmartScreen warns "unrecognised app" | The exe is unsigned. Click "More info" → "Run anyway", or sign it with `signtool` and a code-signing certificate. |
| The window never appears | Read the log file above. A missing DLL typically means the `dist\ARINC717Reader` folder was copied incompletely. |
| "PDF import needs the 'pymupdf' package" inside the exe | The build was made from a venv without PyMuPDF; rerun the script (it installs `.[ocr]`, which includes it). |
| OCR unavailable inside the exe | Same for `rapidocr-onnxruntime`; check `dist\ARINC717Reader\_internal\rapidocr_onnxruntime\models\` contains three `.onnx` files. |
| Antivirus quarantines the exe | A known false positive with PyInstaller builds; add an exclusion or sign the build. |
| Build fails with a `py -3.12` error | Python 3.12 is not installed or not on PATH; install it from python.org. |
| `ImportError: attempted relative import` at start | The spec must point at `packaging/launcher.py`, not at the package's `__main__.py`. |
